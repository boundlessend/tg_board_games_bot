НА-СТОЛ-КИ by senya

Telegram-бот с помощниками для настольных игр. Помощники: «Опасные слова» (слова, проклятья, боссы) и словесные игры «Крокодил», «Алиас», «Кто я?». Есть дискуссионная игра «Бункер» с автоматическим ведением партии в групповом чате. Контент выдаётся без повторов для каждого Telegram ID, история хранится в SQLite. Есть инлайн-режим и админ-меню со статистикой и добавлением контента.

## Установка

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка

```bash
cp .env.example .env
```

В `.env` укажите токен и (опционально) Telegram ID администраторов через запятую:

```env
BOT_TOKEN=your_real_telegram_bot_token
ADMIN_IDS=11111111,22222222
```

Без `ADMIN_IDS` админ-меню недоступно никому. Администраторы получают короткое сообщение при каждом запуске бота, чтобы незаметных перезапусков не было.

## Запуск

```bash
python bot.py
```

При первом запуске рядом с кодом создаётся `bot.sqlite3`.

### Docker Compose (рекомендуется)

```bash
cp .env.example .env    # укажите BOT_TOKEN (и опционально ADMIN_IDS)
docker compose up -d    # сборка образа и запуск в фоне
docker compose logs -f  # логи
docker compose down     # остановить
```

Compose поднимает два сервиса:

- `bot` - сам бот на long polling. База лежит в томе `db` (`DATABASE_PATH=/db/bot.sqlite3` зашит в образ), поэтому история выдач и активные партии переживают перезапуски. У контейнера есть healthcheck: бот раз в 30 секунд обновляет отметку живости, и если polling завис, Docker перезапустит контейнер.
- `backup` - раз в сутки снимает бэкап базы (`VACUUM INTO`) в том `backups` и хранит последние 7 снимков. Интервал и глубину хранения можно поменять в `command`.

Логи обоих сервисов ротируются (3 файла по 10 МБ), у контейнеров задан лимит памяти. Токен передаётся через `env_file`, в образ `.env` не попадает.

Достать бэкап с хоста:

```bash
docker compose cp backup:/backups ./backups
```

### Docker вручную

```bash
docker build -t tg-board-games .
docker run --rm --env-file .env -e DATABASE_PATH=/db/bot.sqlite3 -v tg-board-games-db:/db tg-board-games
```

Образ работает от непривилегированного пользователя, поэтому база должна лежать в томе `/db`: флаг `-e DATABASE_PATH=/db/bot.sqlite3` задаёт путь явно. Если оставить `DATABASE_PATH` пустым, бот попытается создать базу в `/app`, куда у пользователя нет доступа на запись, и упадёт при старте. `--rm` подходит для запуска по требованию; для постоянного аптайма используйте `-d --restart unless-stopped`.

## Данные

- `data/words.json` - обычные и фэнтези-слова «Опасных слов».
- `data/curses.json` - проклятия.
- `data/bosses.json` - боссы.
- `data/crocodile.json`, `data/alias.json`, `data/whoami.json` - пулы слов для «Крокодила», «Алиаса» и «Кто я?».
- `data/bunker.json` - пулы карт игры «Бункер» (катастрофы, суперсилы, фобии, характер, хобби, багаж, факты, особые условия, угрозы, карты бункера).

Пулы можно расширять из админки: пользовательский контент хранится в SQLite и добавляется к файловым словам при выдаче. В сообщениях показывается счётчик выдачи относительно размера пула. В «Опасных словах» слова после исчерпания пула заканчиваются, проклятья и боссы начинают новый круг. В «Крокодиле» и «Алиасе» слова после исчерпания идут на новый круг (если включён авто-цикл).

Меню работает на inline-кнопках (сообщение редактируется на месте). Список команд виден в меню Telegram-клиента:

| Команда | Где | Что делает |
| --- | --- | --- |
| `/start` | везде | открывает меню; в личке ещё и разрешает боту писать вам, без этого не дойдут слова и карты |
| `/help` | везде | справка по боту |
| `/play` | беседа | выбор командной игры |
| `/bunker` | везде | в беседе открывает партию, в личке выдаёт код режима «отдельно» |
| `/joinbunker КОД` | личка | вход в партию по коду |
| `/fav`, `/favorites`, `/favclear` | личка | избранное |
| `/forgetme` | личка | удалить все свои данные |

Админские команды в меню не публикуются, они перечислены в разделе «Админ-меню».

Два режима по типу чата:

- В личке с ботом доступна игра `Кто я?` - тяни персонажа кнопкой.
- В беседе (добавьте бота в группу) доступны `Крокодил`, `Алиас`, `Опасные слова` и `Бункер`.

Инлайн-режим: наберите `@имя_бота` в любом чате, чтобы получить случайные слова (без учёта истории).

В личном меню есть `Настройки`: переключатель авто-цикла словесных игр (при «выкл» после исчерпания слов нужно нажать «Новая игра»).

Избранное: `/fav` сохраняет последнее выданное слово, `/favorites` показывает список, `/favclear` очищает.

## Командные словесные игры (беседа)

`Крокодил` и `Алиас` в беседе идут по командам:

1. Создатель открывает игру из меню, в лобби выбирает число команд (2-4) и время хода (30/60/90 с), игроки вступают в команды кнопками, создатель жмёт «Начать». В лобби есть кнопка «Открыть ЛС с ботом»: слова приходят в личку, поэтому её нужно открыть заранее.
2. Игрок команды, чей ход, жмёт «Слово в ЛС» - бот присылает слово ему в личку и запускает таймер хода. Если личка закрыта, бот скажет об этом, а слово вернётся в пул. Если слово берёт другой игрок той же команды, бот сообщит в чат, что объясняющий сменился.
3. «Угадали +1» начисляет очко и закрывает слово: следующее берут кнопкой «Слово в ЛС». «Пропустить» меняет слово без очка, «Реролл (-1)» - со штрафом в очко (счёт может уйти в минус), «Передать ход» отдаёт ход другой команде.
4. «Завершить» доступно любому участнику, но спрашивает подтверждение, чтобы партию нельзя было закрыть случайным нажатием. «Отмена» в лобби доступна создателю и администраторам чата.

Команда `/play` открывает тот же выбор игр.

## Опасные слова (беседа)

В беседе `Опасные слова` - игра на 2 команды, где бот работает крупье: счёт и запретные слова игроки ведут «вживую» на своём поле. Обе команды играют одновременно, у каждой своя дорожка.

1. Ведущий открывает игру из меню. На табло видно состояние обеих дорожек: взято ли слово, кто объясняет, отправлено ли слово.
2. Игрок жмёт «Я объясняющий 1/2» - он будет объяснять слово своей команде. Соперник жмёт «Тянуть слово 1/2»: секретное слово этой команды приходит ему в личку, и его команда пишет к нему запретные слова. Когда готовы, «Отправить 1/2» отправляет то же слово объясняющему. В общий чат слово не попадает.
3. «Новый раунд» сбрасывает обе дорожки.
4. «Проклятие» тянет случайное проклятие с выбором «Принять / Реролл / Убрать»: реролл заменяет его новым и возвращает отвергнутое в колоду партии, «Принять» оставляет его в чате, «Убрать» снимает предложение целиком. Кнопка «Босс» работает так же и выбирает единственного босса партии (финальный ход); после «Принять» табло сразу показывает, что босс раскрыт.
5. «Завершить» закрывает партию.

Проклятия, боссов, новый раунд и завершение запускает ведущий (кто открыл игру) или администратор чата - так партия не зависнет, если ведущий ушёл. Таймера хода в этой игре нет: раунд не ограничен по времени по правилам самой игры.

Состояние партии снапшотится в SQLite и переживает перезапуск бота.

## Бункер

Дискуссионная игра на выживание для группового чата. Добавьте бота в беседу и отправьте `/bunker`:

1. Игроки жмут «Вступить в бункер» (нужно от 4 до 16). При вступлении бот сразу пишет игроку в личку: если личка закрыта, игрок помечается в лобби значком и предупреждением, так что проблема видна до старта, а не в момент раздачи. В лобби есть кнопка «Открыть ЛС с ботом».
2. Создатель жмёт «Начать»: бот раздаёт карты в личку, открывает катастрофу и план партии (мест в бункере и сколько изгнать по числу игроков). Если кому-то карта не дошла, партия не начинается, а повторное «Начать» дошлёт те же карты только тем, кто их не получил.
3. Каждый раунд (всего 5): открывается пара «Бункер + Угроза», игроки кнопкой «Открыть мою карту» раскрывают по одной карте (порядок фиксированный: суперсила, фобия, характер, хобби, багаж; факт раскрывается в финале).
4. Голосования за изгнание идут по таблице раундов из правил. Голоса принимаются тайно, при ничьей - переголосование среди равных, затем случайный выбор.
5. После 5 раундов оставшиеся попадают в бункер - в базовом режиме это победители.

Табло правится на месте, а не публикуется заново на каждой фазе, поэтому в чате не копятся сообщения с живыми кнопками. Отменить партию может создатель или администратор чата.

В лобби кнопкой переключается режим: «базовый» (победители - все попавшие в бункер) или «история выживания» (развёрнутый финал, см. ниже).

### История выживания

Если в лобби выбран этот режим, после 5 раундов разыгрывается финал:

- Группа в бункере тянет одну из открытых за игру угроз, изгнанные - две случайные.
- По каждой угрозе и затем по катастрофе идёт общее голосование «Справились / Не справились» (голосуют все, включая изгнанных): «справились» - если хотя бы половина считает, что у группы хватает полезных карт.
- При провале разыгрывается случайная потеря: гибнет один член группы или (с шансом «карты угрозы») вся группа; провал катастрофы губит всех выживших.
- В итоге бот объявляет, кто пережил историю.

Особые условия раздаются в личке вместе с картами и разыгрываются голосом. Состояние партии снапшотится в SQLite и переживает перезапуск бота.

### Режим «отдельно» (без беседы)

Если игроки рядом и общей беседы нет, играют через код-приглашение в личке с ботом:

1. Создатель пишет боту `/bunker` в личке - бот выдаёт код игры из шести символов (буквы и цифры, без похожих `0`/`O` и `1`/`I`).
2. Остальные открывают ЛС с ботом и вводят `/joinbunker КОД` (нужно 4-16 игроков). Регистр кода не важен.
3. Создатель жмёт «Начать»: каждому в личку приходит его секретный набор карт персонажа, общая катастрофа, план партии и пары «Бункер + Угроза» по раундам.

Дальше партия идёт «вживую»: игроки сами раскрывают карты по одной каждый раунд и голосуют за изгнание. Бот в этом режиме выступает крупье (раздаёт карты и общий стол), без автоведения раундов. Развязка «История выживания» в режиме «отдельно» тоже проводится игроками вручную.

## Активные партии и их срок жизни

Все активные партии (групповые сессии слов, «Опасные слова», «Бункер» и лобби режима «отдельно») сохраняются в таблицу `session_state` и восстанавливаются при старте бота. Не восстанавливается только таймер хода: начатый ход доигрывают вручную.

Партии, в которых не было активности больше суток, считаются брошенными и удаляются при следующем запуске бота, чтобы не занимать свои чаты навсегда.

## Данные пользователя

Бот хранит по каждому Telegram ID: историю выданных слов, проклятий и боссов (чтобы не повторяться), избранное, настройку авто-цикла и последнее выданное слово. Имена и тексты сообщений не сохраняются.

Команда `/forgetme` удаляет всё перечисленное по вашему ID (с подтверждением). После неё история выдач начинается с нуля.

Админский `/backup` отправляет файл базы в чат Telegram: файл содержит Telegram ID всех пользователей и остаётся на серверах Telegram, поэтому пользоваться им стоит осознанно.

## Админ-меню

Добавьте свой Telegram ID в `ADMIN_IDS` в `.env` и отправьте боту команду `/admin` в личном чате. Доступ к админ-меню есть только у ID из списка и только в личке.

Бот покажет сводку: число пользователей, выдачи по видам («Опасные слова», проклятия, боссы, слова словесных игр), общую сумму, выдачи и активных пользователей за 7 дней, топ-10 слов. Числа разложены по видам, поэтому сумма сходится с показателем за 7 дней, который тоже считает все игры.

Кнопки: `Полный отчёт` - подробная статистика по каждому Telegram ID одним файлом, `Выгрузить CSV` - сводка файлом, `Активность` - выдачи по дням за 14 дней, `Закрыть админку` - выход.

Команды добавления контента (только для админов, в SQLite):

- `/addword <игра> <слово>` - игры: `dangerous_words`, `crocodile`, `alias`, `whoami`.
- `/addcurse <название> | <описание>`
- `/addboss <имя> | <описание>`
- `/listcontent` - показать добавленный контент.
- `/delword <игра> <слово>`, `/delcurse <id>`, `/delboss <id>` - удалить добавленное.
- `/importwords <игра>` - подпись к файлу (JSON-массив или слова по строкам/через запятую) для массового добавления слов. Файлы больше 1 МБ отклоняются, весь пак пишется одной транзакцией.
- `/backup` - получить файл базы.
- `/restore` - прислать файл `.sqlite3` с подписью `/restore`. Перед заменой бот проверяет сигнатуру файла и наличие таблиц этого бота, а текущую базу сохраняет в `.bak` рядом.

## Устройство кода

- `bot.py` - сборка приложения: конфиг, хранилище, роутеры, общий обработчик ошибок, публикация списка команд.
- `config.py` - чтение окружения, `constants.py` - тексты кнопок и callback-данные.
- `database.py` - схема SQLite и все запросы.
- `handlers/` - роутеры aiogram по играм и разделам, `handlers/common.py` - общие фильтры, блокировки чатов и отправка с ретраями.
- `services/content.py` - модели контента и загрузка json, `services/picking.py` - выбор без повторов, `services/bunker.py` и `services/bunker_state.py` - правила и состояние «Бункера».
- `health.py`, `logging_setup.py`, `scripts/backup.py` - эксплуатационная обвязка.

## Добавление игр

Простая словесная игра (как «Крокодил»/«Алиас»):

1. Положите файл `data/<game>.json` вида `{"words": [...]}`.
2. Добавьте запись в `_WORD_GAME_FILES` в `services/content.py`, указав флаг `private_only` (личная игра или командная).

Кнопка в нужном меню, выдача без повторов и авто-цикл подключаются автоматически через `handlers/word_games.py`.

Сложная игра со своей механикой (как «Опасные слова»): создайте роутер в `handlers/` и подключите его в `bot.py`; выдачу без повторов можно переиспользовать из `services/picking.py`.

## Разработка

Проверки (их же гоняет CI на каждый push и pull request):

```bash
pip install -r requirements-dev.txt
ruff check .
ruff format --check .
mypy .
pytest --cov=. --cov-report=term-missing
```

Тесты разложены по слоям:

- `tests/test_content.py` - загрузка и валидация контента, разбор конфигурации.
- `tests/test_storage.py` - SQLite: выдачи без повторов, пользовательский контент, аналитика, снапшоты сессий, бэкап и восстановление.
- `tests/test_game_logic.py` - чистые правила игр без телеграма.
- `tests/test_handlers.py`, `tests/test_bunker_flow.py`, `tests/test_personal.py`, `tests/test_admin.py` - сценарии целиком через `Dispatcher.feed_update` с фейковой сессией Telegram (`tests/fake_bot.py`): права, фазы партии, доставка сообщений в личку.
- `tests/test_ops.py` - бэкапы с ротацией, отметка живости, формат логов.

Версии зависимостей зафиксированы точно, обновления приносит Dependabot отдельными PR. CI дополнительно проверяет форматирование, валидность `docker-compose.yml` и прогоняет `pip-audit` по зависимостям.
